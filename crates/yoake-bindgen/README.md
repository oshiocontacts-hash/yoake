# yoake-bindgen

Generates the engine glue (`yoake_glue/*.rs`), the guest stubs and the reports from rustdoc JSON of the engine
crates; `regen.sh` runs rustdoc and the generator (`regen.sh --check` compares instead of writing).

## `ids.lock.json`

Binding ids are assigned once and never reused or renumbered (`Lock::assign`, `append_only_violations`).

* `reserved` is a list of id ranges the generator **never allocates into**: a new binding gets the next free id after
  `max id + 1`, skipping any reserved range. The list is for modules whose bindings are assigned by hand later
  (`custom_mobs`, 1515..=2514, FR-F4-MOB F4M-0). An entry inside a reserved range is a violation
  (`Lock::reserved_violations`, also part of `append_only_violations`); an `unbound` sentinel entry at the end of
  the range (`custom_mobs::__reserved_range_end`) is allowed and keeps the range visible in the entry list.
* A branch that was cut before a range was reserved may have handed out ids inside it. Merge it by keeping the
  merged lock and renumbering the branch's new bindings after the range (their glue is regenerated by `regen.sh`;
  nothing committed refers to the ids except the generated files).
