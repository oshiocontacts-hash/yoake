# 3. ゲームに入れて遊ぶ・すぐ試す

MOD をビルドしたら、実際に Yoake のゲーム内で動かしてみましょう。
大きく分けて **「`yoake dev` で開発中にすぐ試す方法」** と **「`.yak` パッケージとして入れる方法」** の 2 つがあります。

---

## 3-1. `yoake dev` と `YOAKE_WASM_DEV_DIR` ですぐ試す（開発中におすすめ）

自分で MOD を作っている最中は、毎回 `.yak` を作って導入し直すよりも、**開発者モード（ホットリロード）** を使うのが一番手軽です。

### 仕組み（`docs/yoake-wasm-dev.md` より）

ゲームを起動するときに次の 2 つの環境変数を設定します。

1. **`YOAKE_DLL_MODS_UNSIGNED=1`**
   - 署名されていない開発中のローカル MOD の読み込みと、ファイル変更の監視（1 秒に 1 回のポーリング）を有効にします。このフラグが無い場合、以下の開発用読み込みやホットリロードは動作しません。
2. **`YOAKE_WASM_DEV_DIR=<フォルダのパス>`**
   - 指定したフォルダの中にある `<id>.wasm` ファイルを、`.yak` パッケージ無しでそのまま MOD として読み込みます。

この状態で MOD のプロジェクトフォルダから次のコマンドを実行します。

```sh
yoake dev
```

`yoake dev` は、以下をまとめて行います。

1. MOD をビルドする（`yoake build` と同じ）
2. マニフェストや `.wasm` を検査する（`yoake check` と同じ）
3. 環境変数 `YOAKE_WASM_DEV_DIR` が設定されていれば、ビルドされた `.wasm` をそのフォルダへコピーする

### ホットリロード（ゲームを起動したまま更新）

`YOAKE_DLL_MODS_UNSIGNED=1` を付けてゲームを起動している間、ゲームは 1 秒おきに `.wasm` ファイルの更新をチェックします。

- `yoake dev` で `.wasm` ファイルが変わったあと、次の確認までそのままだったら、次のフレームまたはティックで新しいインスタンスに自動で差し替わります。
- 万が一、新しくビルドした `.wasm` の読み込みに失敗しても、ゲームは落ちずに **1 つ前の正常なインスタンスがそのまま動き続けます**（ログに警告が 1 行出ます）。

> [!NOTE]
> - ホットリロードが対応しているのは標準の **`client-mod` ワールドのモジュールのみ** です。
> - フルカタログ版（`client-full` / `server-full`）のモジュールはホットリロード対象外で、ゲーム起動につき 1 回読み込まれます。

---

## 3-2. `.yak` パッケージをどこに置くか

`yoake pack` を実行すると、プロジェクト内の `dist/<id>-<version>.yak` にパッケージファイルが出力されます。

```sh
yoake pack
```

### ゲーム本体の読み込みの仕組み

`docs/api/yoake-mods.md` および `docs/yoake-wasm-dev.md` にある通り、パッケージの展開と一覧ファイルの管理は次のように行われます。

- `.yak` の展開（`<game dir>/yoake-mods/<id>/<version>/` への配置と `yoake-mods/.cache/` へのアーカイブ保持）と `<game dir>/yoake-mods.txt`（1 行につき `<id> <version>` の形式）の更新は **ランチャー** が行います。ゲーム本体は展開済みのフォルダだけを読み込み、プレイヤーが手作業でフォルダを配置する仕組みではありません。
- 専用サーバー（`--dedicated`）でも、`--game-dir` の `yoake-mods.txt` に書かれたパッケージからサーバーモジュール（`server-full`）を読み込みます。
- 未署名の手作り `.yak` を読ませるには、環境変数 `YOAKE_DLL_MODS_UNSIGNED=1` が必要です（`YOAKE_DLL_MODS_UNSIGNED=1` を付けると、インストール済み `.yak` 内の未署名 `client-mod` モジュールも 1 秒おきにホットリロード監視されます）。

### `.yak` の入れ方（未確定）

- `.yak` の展開と `yoake-mods.txt` の更新はランチャーが行い（`docs/api/yoake-mods.md`）、ランチャーのコードにはローカルの `.yak` ファイルを扱う処理（`launcher/src/yoake_mods/plan.rs` の `plan_local`）がありますが、ランチャーの画面操作の手順はドキュメントに記載がないため **（未確定）** です。

## 3-3. 動作確認とログの見方

ゲームが起動すると、WebAssembly エンジンが動いているかどうかが起動ログに 1 行出力されます。

- MOD が 1 つも無いとき: `wasm: no mods (engine not started)`
- MOD が読み込まれたとき: `wasm: N mod(s), engine started`（`N` は読み込まれた MOD の数）

また、MOD の中から出力したログ（`yoake_wasm_sdk::log(...)` や、標準ライブラリ有効時の `println!` / `eprintln!`）もゲームのログに出力されます。画面に HUD が出ないときやコマンドが動かないときは、まず起動ログに `wasm: N mod(s), engine started` が出ているかを確認しましょう。
