# Yoake を Forge・Fabric 以上の自由度にする計画（2026-11-20、設計：Claude）

## 持ち主の決定（11/20）
「Mixin どこでも書き換えられるレベルにしてほしい」「グループ内でしか使わないものだから自由度を最優先」「閉じるのももうほぼ無くしたい」「ファイルや通信もしよう」「やることも全部やろう」「作成には Sonnet, kimi, agy から hydrogen でコーディング」。

## 残す決まり（これだけ）
- MOD が入っていないとき、バニラの動きを一切変えない（フックは空なら元の処理だけ）。
- ランチャーでの「許可」のクリックは残す（ファイルのハッシュで許可。入れた MOD が何でもできることは確認画面に書く）。
- 署名の鍵は `C:\YoakePrivate` だけ。Minecraft のファイル・デコンパイルしたソース・prepare 済み資源は commit しない。
- ゲームのメインスレッドを MOD が止めない（重い仕事・待ちは worker で）。止めるのは「自由を狭める」ためではなく、ゲームが固まらないため。
- 署名なしのネイティブ DLL は使わない（参加者の PC で Smart App Control が止めるため）。自由は WASM の側で出す。

## 段階
| 段 | 中身 | 終わりの判定 |
|---|---|---|
| F1 フックを全部に | フック生成器（codemod）を、ゲームのクレート全部の全モジュールにかける（今は 5 モジュール・709 か所・橋渡し 201）。橋渡しできない型は「不透明なハンドル」で渡す。全構造体のフィールドに getter/setter を生成（Forge の access transformer 相当）。呼び出し箇所のフック（INVOKE の差し替え）も全部に。性能の除外は「測って 1% を超えた所」だけに減らす | MOD なしの tick・フレーム時間の増加が 1% 未満、フックの数が数千〜万、見本 MOD で任意の関数を差し替え |
| F2 砂箱をほぼ無くす | 砂箱 WASM：ファイル（MOD 自身のデータフォルダー＋ゲームフォルダー、望めば任意の場所）、TCP/UDP・名前解決、HTTP（wasi-http）。フルアクセス：WASI（std が動く）＋同じファイル・通信。待ちの長い仕事は MOD の worker（別スレッドの別インスタンス、メッセージでやり取り）で | MOD が HTTP POST・ファイル保存・ソケットを使える。メインスレッドは固まらない |
| F3 本体のバニラ機能を埋める | ディメンション（`enum Dim` を登録式に、データパックの dimension / dimension_type、実行中に作る・消す）、データパックの worldgen（バイオームソース・noise settings・density function・carver）、チャンク生成の差し替え口 | バニラのデータパックのディメンションが動く。MOD がディメンションを作って生成を差し替えられる |
| F4 登録できるものを増やす | 自作のモブ（AI・当たり判定・モデル・アニメ）、実行中に作るテクスチャ、IME の変換中文字、フルアクセスの HUD・ワールド描画、パーティクルの処理、音の流し込み、BER、設定画面など（GAP2 の表の穴を全部） | GAP2 の表で missing / partial が 0 |
| F5 作る人向けの仕上げ | SDK・キット・ガイド（日英）・見本・WIT の版上げ。製作班の ZIP 更新 | キットで全部の新機能の見本が動く |

## 進め方
- 統合ブランチ：`yoake-free/merge`（`vps/yoake2/merge` 862d10c89 から）。作業ごとに worktree とブランチ。
- 実装：Sonnet（このPC、worktree ごと）、ノート PC の「Yoake coding」（Kimi K3.1・agy Gemini Hydrogen）。Claude は設計・仕様書・分担・レビュー。Fable は段の区切りでまとめて 1 回。
- ディスク：同時ビルドは 2 つまで（C: の空き 30 GB 前後）。終わった target は消す。
- 各作業はレポート（`docs/yoake2/reports/FR*.md`）を残し、わからない所は「要確認」に書く。
