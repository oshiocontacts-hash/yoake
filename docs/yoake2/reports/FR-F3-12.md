# FR-F3-12: dimension model (F3-1) and `yoake:grid` biome source (F3-2)

Branch `yoake-free/f3-12` on `yoake-free/merge` + F3-0 (160c39a83). Only `horizon-world` changed; no consumer was touched.

## F3-1: `crates/horizon-world/src/dimension.rs`
* `DimensionType`: `min_y, height, logical_height, has_skylight, has_ceiling, has_ender_dragon_fight, has_fixed_time,
  coordinate_scale, ambient_light, infiniburn, monster_spawn_light_level (IntProvider: constant/uniform/other kept
  verbatim), monster_spawn_block_light_limit, default_clock, timelines (tag or list), skybox, cardinal_light,
  attributes (map)`. Field set was read from the prepared 26.3 `dimension_type` data (not copied).
* 26.3 moved `ultrawarm`, `natural`, `piglin_safe`, `has_raids`, `bed_works`, `respawn_anchor_works`, `effects` and the
  sky/fog/cloud/audio values into `attributes` (`minecraft:gameplay/...`, `minecraft:visual/...`). The attribute map is
  kept verbatim; typed accessors exist for the gameplay ones the engine reads: `fast_lava`, `water_evaporates`,
  `piglins_zombify`, `can_start_raid`, `respawn_anchor_works`, `snow_golem_melts`, `nether_portal_spawns_piglin`
  (with vanilla defaults). Pre-26 flat fields `ultrawarm, piglin_safe, has_raids, respawn_anchor_works, fixed_time` are
  accepted and folded in (an explicit attribute wins). `natural`, `bed_works`, `effects` are not folded (ignored).
* Parsing: `min_y` and `height` required, everything else defaults like `LevelHeight::of_json` did. Validation with
  clear `DimensionError`s: min_y/height multiples of 16, height >= 16, -2032 <= min_y, min_y+height <= 2032, logical
  height within height, scale 1e-5..=3e7, light 0..=15, uniform min <= max, infiniburn must be a tag.
  `to_value()` / `from_value()` round-trip exactly.
* `LevelStem { dimension_type: TypeRef (Id | Inline), generator: GeneratorSpec (Noise{settings Id|Inline, biome_source:
  BiomeSourceDefinition} | Flat(settings JSON) | Debug) }`. Parse/serialize take the `BiomeSourceCatalog` (biome ids are
  registry-validated). Other generator types give `UnknownGeneratorType` (mod generator is F3-5).
* `DimensionTypeRegistry` (vanilla built in; `load(bundle)` layers JSON text over it, bad entries reported and skipped,
  vanilla id keeps its built-in), `LevelRegistry` (types + stems, `insert_stem` checks the type resolves, `level_type`,
  `level_height`, `load_preset_stems` for world-preset `dimensions`). F3-3 fills it.
* `LevelHeight::vanilla` now delegates to `DimensionType::vanilla(..).level_height()` (single source). `LevelHeight::
  of_json/of_type` and `WorldgenOverrides` unchanged; no consumer change.
* Vanilla built-ins: the test compares against literals for the four types (range, sky, ceiling, ambient 0/0.1/0.25,
  clock, scale 1/8) = `LevelHeight::vanilla` before the change + `horizon-protocol::DimensionType::vanilla` today.

## F3-2: `yoake:grid`
* `BiomeSourceDefinition::Grid { cell_size, origin: [x, z], width, depth, cells: Vec<String>, outside, seed }`; JSON
  `{"type":"yoake:grid","cell_size":16,"origin":[-16,-16],"width":2,"depth":2,"cells":[...row-major, x fastest],
  "outside":"ns:biome","seed":N}`. `origin` defaults to [0,0], `seed` to 0. Rules: `cell_size` a positive multiple of 4,
  origin multiples of 4, width/depth 1..=256, `cells.len() == width*depth`, every biome id in the catalog.
  `seed` is carried (for the mod generator that made the grid); lookup is seed-independent.
* Runtime `GridBiomeSource` (new `biome_source/grid.rs`): palette + `u16` cell index array, O(1) per quart sample with
  `div_euclid` in i64 (negative, outside and `i32::MIN/MAX` safe); height ignored. `ResolvedBiomeSource::Grid`,
  `BiomeSourceResolver::Grid`, `possible_biomes` (cells plus outside). The generator already decodes stems through the
  catalog and samples through the resolver, so a stem naming `yoake:grid` builds with no generator change. Vanilla
  types and their encoders are untouched.

## Needs checking
* Tests needing prepared game resources (worldgen parity golden tests A/B, parity scripts) were not run unless they ran
  inside `cargo test -p horizon-world` without resources; those skipped or ignored by the suite are not counted here.
* No decoration smoke test on a 3-biome grid was written: it needs the prepared bundle (feature/structure data). A stem with a
  grid is only parse/resolve tested.
* Vanilla `attributes` built in are the gameplay ones only; visual/audio attributes (sky, fog, cloud, music) and the
  `bed_rule` error message come from the prepared bundle through `DimensionTypeRegistry::load`. F3-3 must feed the
  bundle in, else a custom reader of `attributes["minecraft:visual/..."]` sees nothing for vanilla types.
* `natural`, `bed_works`, `effects` pre-26 fields are ignored on parse.
* Stem serialization needs the biome catalog (the biome source encoder validates). F3-3 must keep one.
* A grid holds up to 65536 cells as id strings in the stem JSON (about 2 MB at worst); a binary or palette form could
  come later if saves of large grids matter.
* Some touched files have mixed CRLF/LF endings in the working tree; `runtime.rs` was normalized to LF (git stores LF).
* `cargo check -p horizon-client` was not run (no call sites touched).
