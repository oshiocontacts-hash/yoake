# FR-F2: files and network for WASM mods

Branch `yoake-free/f2` (worktree `horizon-f2`, from `yoake-free/merge` 862d10c89). Owner decision 2026-11-20: mods are
used only inside their group, so they may do what a Forge/Fabric mod can. Kept: no change without a mod installed; the
game thread never blocks on a mod.

## What changed

**New crate `crates/yoake-mod-io`** (shared by the sandboxed route and the core-module runtime):

- `files.rs`: preopens. `/data` = `<game dir>/mod-data/<mod id>/` (created, read-write), `/game` = the game dir
  (read-write), and with `[wasm] host_filesystem = true` every local drive root as `/host/<lowercase letter>`
  (Windows: fixed and removable drives via `GetDriveTypeW`; Unix: `/host/root`). The mod id must be
  `[A-Za-z0-9._-]`, not starting with a dot. File calls run on the calling thread (`allow_blocking_current_thread`).
- `queue.rs`: bounded byte-message queue (1024 messages / 16 MiB, `push` never blocks, `Full` / `TooLarge` / `Closed`).
- `worker.rs`: `WorkerHandle`. A component on its own OS thread, own Store, full WASI p2 (`add_to_linker_sync`),
  `wasi:http` (`wasmtime-wasi-http =48.0.7`, default send-request with rustls), `inherit_network`, TCP/UDP/name lookup,
  no fuel, no clock bound, 256 MiB memory limit. Host functions `host-send`, `host-recv` (blocking), `host-try-recv`.
  Export `yoake:mods/worker-run@1.3.0` `run`. A trap/exit/instantiate failure ends only the worker (one log line). Stop:
  queues closed, epoch interrupt (10 ms ticker), 0.5 s grace, then the thread is let go. `Drop` stops it.
- `pipe.rs`: line-splitting stdout/stderr -> `wasm mod <id> [stdout]: ...` log lines (same shape as the sandboxed route).

**WIT** `crates/yoake-wasm/wit-worker/yoake-worker.wit`, package `yoake:mods@1.3.0` (new interfaces `worker`,
`worker-host`, `worker-run`; worlds `worker-user`, `worker-mod`). Generated by `horizon-mod-api-gen`
(`generate_worker_wit`, committed-file test, same pattern as the 1.1/1.2 inject WIT). No existing interface or the 1.0
baseline was touched.

**Sandboxed components (`yoake-wasm`)**: sockets (tcp, udp, create-socket, network, instance-network, ip-name-lookup) and
`wasi:http` (types, outgoing-handler) are linked and in the import allow-list; `yoake:mods/worker@1.3.0` is an allowed
import (`worker-send`, `worker-recv`). `Sandbox::set_mod_io(id, ModIo)` gives a mod its folders/worker before it is
compiled (no signature of `ClientMod::instantiate` etc. changed; lookup by mod id at `CompiledComponent::instantiate`).
The main instance keeps `BoundedClock` (waits over 2 ms trap). **The main instance may not use sockets or `wasi:http`**:
the WASI context denies tcp/udp/lookup and the http hooks answer `HttpRequestDenied`. `Sandbox::set_main_network(true)`
lifts it (tools/tests only). Reason: `poll`/`blocking_*` on a socket would block the game thread, and bounding every
blocking stream function was not practical. `[wasm] permissions` still parse; `PackageServices::require` now always
grants (config, permissions, storage); the gate tests were changed accordingly.

**Full-access core modules (`yoake-slice`, `yoake-guest-sdk`)**: `ModConfig.io: Option<ModIo>`. WASI preview 1
(`wasmtime-wasi` `p1`) is linked into every core module (a module that imports nothing from WASI loads as before),
with the same preopens; stdout/stderr go to the same `wasm mod <id> [stdout|stderr]: ...` lines; wall/monotonic
clocks and random work. `poll_oneoff` is replaced by a bounded one (waits over 2 ms trap, the rule of the sandboxed
route). Env imports `yoake_worker_send(ptr,len)` and `yoake_worker_recv(ptr,cap)`; SDK `yoake_guest_sdk::worker::{send,recv}`.
Persistent storage is files under `/data`.

**Manifest / loader**: `[wasm] worker = "bin/wasm/<name>.wasm"` and `host_filesystem = true` (`horizon-mods`;
`Wasm::declared_files()` includes the worker so it is packed, size-checked and classified as a wasm part; `modules()`
is unchanged for the build tools). Loaders: `wasm_mods.rs`/`yak_mods.rs` (`register_io`, `WasmMod.worker`,
`host_filesystem`) and `yoake2_mods.rs` (`cfg.io` from the archive, `Archive::worker_module`).

**Docs**: `docs/yoake2/MOD-GUIDE.md` and `.ja.md` section 14, `docs/guide-ja/09-files-network.md` (+ README entry),
`docs/yoake-wasm-dev.md` (sandbox text), `rust-toolchain.toml` adds target `wasm32-wasip1`.

## About `service.http`

The manifest accepts `[wasm] permissions = ["service.http"]` and `Wasm::has_permission`/`WASM_PERMISSIONS` list it, but no
service or transport reads it (`grep service.http` finds only the manifest list). It is now moot: HTTP is `wasi:http`
in a worker. Nothing was removed (old mods keep parsing). Recommendation: keep the string accepted but treat it as a
no-op, and remove it from `WASM_PERMISSIONS` in a later cleanup together with the other now-ungated ones
(`service.config`, `service.storage`, `service.permissions`).

## 要確認 / Needs checking

1. **Not run in a real game.** The loader wiring (`wasm_mods.rs::register_io`, `yak_mods.rs`, `yoake2_mods.rs`) compiles
   (`cargo check -p horizon-client --features yoake2-slice`) but no `.yak` with a worker or `host_filesystem` was
   installed and loaded through it; the manifest parse and pack paths have a unit test, the engine paths have the
   crate tests above.
2. **Main-instance network is denied, not bounded.** The brief says to enable sockets/http for sandboxed components and
   keep the main instance non-blocking. Linking them but denying use in the main instance was the simplest way to keep
   "the game thread never blocks" (a socket `poll` or `blocking-read` cannot be bounded without re-implementing the
   WASI stream functions). If the owner wants main-instance TCP anyway, `Sandbox::set_main_network(true)` exists but
   is not wired to any manifest field or switch.
3. **File I/O counts against the 20 ms hook budget** and is not extended like service time (`HOST_TIME`). A slow disk
   can disable a mod. The tests relax the limit (`TimeLimits` 10 s) because a loaded machine failed the first file
   call once with the 20 ms default. If file time should extend the deadline, the filesystem host functions need a
   timing wrapper.
4. **`wasm.interface` is not raised.** The new interfaces are package `yoake:mods@1.3.0`, but `SUPPORTED_WASM_INTERFACE`
   stays 1.2 and the manifest rule "minor >= 1 needs `inject-mod`" is untouched; `worker` / `host_filesystem` are
   plain manifest keys. A worker imported by any world is accepted by `check_import`. Whether 1.3 should become a
   declared minor is a decision for the owner (it would touch the manifest checker).
5. **The 1.0 ABI baseline** (`abi-1.0-baseline.wit`, `abi-1.0-ids.json`) is untouched and the additive test is green,
   but the baseline checker only knows `yoake:mods@1.0.0`; the new WIT is guarded by its own committed-file test.
6. **`Host: Send` in yoake-slice** is an `unsafe impl` (the Store never leaves its thread; wasmtime-wasi p1 asks for
   `Send`). Reviewer please confirm the argument in the comment in `runtime.rs`.
7. **Full-access `poll_oneoff` is our own** (clock waits of at most 2 ms succeed at once, files are always ready; an
   absolute monotonic deadline with a non-zero value is refused because its base is the WASI context's). Only clock
   and fd subscriptions are modelled; `std` only uses those.
8. **`cargo-horizon-mod` / `yoake check` / `yoake build`** (`yoake-cli`) do not validate or build the worker component
   (`modules()` was kept client/server only on purpose); the worker is packed and size-checked via `declared_files()`.
9. **One worker per instance**: a package with a client and a server module gets two workers. The worker's `/data`
   is shared with the main instance (same folder). Two instances writing the same file are not coordinated.
10. **`/host/<letter>` on non-Windows** is a single `/host/root` for `/`; not tried on Linux/macOS.
11. **Windows only**: the epoch ticker of the worker engine (10 ms) and the 0.5 s stop grace were tuned by reasoning,
    not measured; a worker blocked in a socket call outlives its mod until that call returns.
12. **New toolchain target**: `rust-toolchain.toml` now lists `wasm32-wasip1` (the std-guest test and full-access std
    mods need it). Installing it was done with `rustup target add wasm32-wasip1`.
13. **Cargo.lock** gained about 40 crates (`wasmtime-wasi-http`, hyper, rustls, h2, http, webpki-roots, ...). rustls is
    used by the default `wasi:http` send-request for `https` URLs; `https` was not tested (no local TLS server).
14. **Binary size / startup**: not measured. The `yoake-wasm` crate and the game now link hyper/rustls.
