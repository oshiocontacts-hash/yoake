# Yoake MOD の作り方の方針（2026-11-14〜、全チャット共通）

この文書は、Yoake 向けの MOD を作っているすべてのチャットへの共通方針です。設計の詳細は `docs/yoake-wasm.md`、`.yak` の形式は `docs/yak-format.md` にあります。

## 方針
- **ゲーム本体は 1 つだけ:** 配るゲーム本体は、MOD を中に組み込まない素の `yoake.exe` 1 つにします。GitHub の公開 CI でビルドし、SignPath で無料のコード署名を受けます。
- **MOD は `.yak` で配る:**
  - **データの `.yak`:** ブロック、アイテム、家具モデル、テクスチャ、音、言語ファイルなど。すでに使えます。
  - **プログラムの `.yak`:** WebAssembly のコンポーネント（`bin/wasm/<名前>.wasm`）。署名済みの本体が JIT で動かします。DLL は使いません。
- **フックと本体の機能は WIT 経由:** MOD が使えるフックと本体の機能は、フックの一覧から自動で作る WIT `yoake:mods@1.x` を通します。窓口の版は足していくだけなので、古い MOD は新しい本体でも動き続けます。
- **MOD のソースは非公開のまま:** 公開するのはエンジン（`oshiocontacts-hash/yoake`）だけです。
- **使うにはコードが要るまま:** ポータルの招待または Discord ログイン、Nestgate のベータコード、スロットコードは、すべてサーバー側で確認します。

## 各チャットで今からできること
1. **データ部分を分ける:** モデル、テクスチャ、音、言語ファイル、ブロックやアイテムの定義は、データの `.yak` にできる形（`horizon-mod.toml` と content フォルダ）にまとめておいてください。
2. **プログラム部分:**
   - **使うものの一覧:** 本体のどのフックと機能を使っているかを、`mods/<id>/WASM-NEEDS.md` に書き出してください。形式は `reports/YK1.md` の表と同じで、「エントリポイント → 何に使うか → 毎フレームか時々か」です。W2 以降で窓口に足す材料になります。
   - **本体の内部に直接触らない:** 本体の内部の型を直接触るコードは新しく増やさないでください。`mod_api` のフックや、Host のサービス越しに書いてください。
   - **WASM ではできないこと:** OS の機能（ファイルを自由に読み書きする、別のプログラムを起動する、マイク、ネット）は、WASM からは直接使えません。本体の機能を通すことになります。必要なら `WASM-NEEDS.md` に「本体側に要る機能」として書いてください。例：リプレイの ffmpeg 起動は、ランチャーか本体が受け持ちます。
3. **WASM への移し替えは、まだ始めないでください:** W1 の窓口が固まったら、このチャット（Yoake 本体のチャット）から各チャットに連絡します。

## 守ること（これまでと同じ）
- Minecraft のゲームファイル、デコンパイルしたソース、prepare 済みのリソースは commit しない。
- MOD が入っていないときに、バニラの挙動を変えない。
- 署名の鍵はリポジトリの外の非公開の場所だけに置き、表に出さない。
- 試すときに、マウスやウィンドウのフォーカスを奪わない（`--offscreen` で起動する）。
