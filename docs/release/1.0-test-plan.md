# Yoake 1.0 手動 E2E テスト計画書

本書は **Yoake 1.0**（Minecraft: Java Edition 26.3 互換の Rust 製ゲームクライアントおよびランチャー）のリリース前手動エンドツーエンド（E2E）テスト手順書です。コードを直接書いていないテスターでもそのまま実施できるよう、各ステップに **手順**・**期待する結果**・**確かめる所**（画面表示・ログ行・ファイル／フォルダー）を明記しています。

> **注記（表記と要確認項目について）**
> - ランチャー UI の日本語表示では、`brand::translate`（`launcher/src/brand.rs`）により翻訳文字列中の `Horizon` / `ホライズン` / `ホライゾン` が原則として `Yoake` に置き換わります（ライセンス表記 `Yoake Launcher は Horizon をもとに作られています（ライセンスは以下のとおりです）` 等を除く）。本書では実際の画面表示に合わせて記載し、必要に応じて英語 UI 表示も併記します。
> - リポジトリ内の仕様・実装に含まれない事項や、別リポジトリ（ポータル側・ゲーム本体側の進行中変更など）に依存する箇所は推測せず **【要確認】** として記載しています。

## 1. 前提と準備

### 1.1 テスト機材・アカウント・対象ビルド・フォルダー一覧（リファレンス）

テストを始める前に、以下の機材・アカウント・ビルドを用意し、データとログの保存場所を把握してください。

#### テスト機材（PC 2 台）
- **PC 1（ホスト／メイン検証機）**: Windows 10（version 1903 以降）または Windows 11（x64）、Vulkan または DirectX 12 対応 GPU。
  - ※Linux（x86_64、Vulkan または OpenGL 3.3 対応 GPU）／macOS（Apple Silicon、Intel Mac は次期 Nightly 以降対応）を併用する場合は該当 OS パスに読み替えてください。
- **PC 2（ゲスト／マルチプレイ検証機）**: フレンド機能（セクション 5）および部屋を開いて参加するテスト（セクション 6）で使用する 2 台目の PC。

#### テスト用アカウント
1. **Minecraft: Java Edition を所有している Microsoft アカウント**（最低 1 つ、2 台同時オンラインプレイ時は 2 つ）
   - 初回の Mojang 公式ゲームファイル（26.3）取得・展開（Prepare）およびオンラインプレイに必須です。
   - 拒否動作の確認用に、**Minecraft: Java Edition を所有していない Microsoft アカウント**が 1 つあると理想的です（任意）。
2. **Yoake ポータルアカウント 2 つ（互いにフレンド関係になれるもの）**
   - **アカウント A（PC 1 用）**: Discord 連携でサインインできるゆにぽっぷメンバーアカウント（または有効な招待コード `YK-XXXX-XXXX` を持つフレンドアカウント）。
   - **アカウント B（PC 2 用）**: Discord 連携メンバーまたは招待コード（`YK-XXXX-XXXX`）で参加したフレンドアカウント。
   - セクション 5 でフレンド申請・承認およびグループ作成を行い、セクション 6 でホスト／ゲストとして使用します。

#### テスト対象ビルド
1. **通常配布版（ポータブル／インストーラー版）**
   - `horizon-launcher-setup.exe`（Windows インストーラー）および `horizon-launcher.exe`
   - ビルド時に Yoake 用の設定値（`YOAKE_PORTAL_URL`、`YOAKE_COMPILED_FEED_URL`、`YOAKE_COMPILED_PUBLIC_KEYS`、`YOAKE_COMPILED_SOURCE_ID="yoake-official"`、Microsoft サインイン用クライアント ID `HORIZON_MSA_CLIENT_ID`）が組み込まれていること（**【要確認】**: テスト対象バイナリに本番またはステージングのどの URL・公開鍵が埋め込まれているかオーナーに確認）。
2. **Microsoft Store 版（MSIX パッケージ）**
   - `YOAKE_DISTRIBUTION=store` でビルドされた `Yoake-<version>-x64.msix`（内部に `YoakeLauncher.exe` と `yoake.exe` を同梱）。
3. **MOD テスト用ツール（セクション 7 用）**
   - Rust 1.95 以降（MOD ガイド 01 の記載。`horizon-mods` の rust-version）、`wasm32-wasip2` ターゲット（`rustup target add wasm32-wasip2`）、`yoake` CLI（入れ方は **【要確認】**: ガイド側も「`cargo install --path crates/yoake-cli` でよいか、配布物があるか」が未確定）、およびゲーム本体実行ファイル（`horizon-client.exe` または `yoake.exe`）と準備済みリソース（`.local/horizon-client/26.3`）。

### ステップ 1-1: 機材・アカウント・ビルドの事前確認

- **手順**:
  1. PC 1 と PC 2 の両方でインターネット接続が有効であることを確認する。
  2. テスト対象の通常版インストーラー（`horizon-launcher-setup.exe` または `horizon-launcher.exe`）と Store 版 MSIX（`Yoake-<version>-x64.msix`）を準備する。
  3. テストに使用する Microsoft アカウント（Java Edition 所有済み）と、Yoake ポータルアカウント 2 つ（PC 1 用・PC 2 用）のログイン情報を手元に用意する。
- **期待する結果**:
  - 2 台の PC でテスト対象バイナリが実行可能であり、必要なアカウント情報とポータル接続先が揃っている。
- **確かめる所**:
  - 配布されたビルドファイルの SHA-256 ハッシュまたはバージョン番号、およびオーナーから共有されたビルド設定情報（**【要確認】**: ステージング／本番ポータル URL・フィード URL・署名鍵のどれが組み込まれたビルドか）。

### ステップ 1-2: クリーンな状態（初期状態）からの開始準備

- **手順**:
  1. 起動中のゲーム（`horizon-client.exe` / `yoake.exe`）とランチャー（`horizon-launcher.exe` / `YoakeLauncher.exe`）をすべて終了する。
  2. 既存のプレイヤーデータを汚さずにクリーンな状態からテストする場合は、PowerShell で一時フォルダーを作成し、以下の環境変数を設定してランチャーを起動する（またはテスト専用 PC で `%APPDATA%\horizon-launcher` と `%APPDATA%\horizon` を退避・削除する）。
     ```powershell
     $TestRoot = Join-Path $env:TEMP "yoake-e2e-$(Get-Random)"
     New-Item -ItemType Directory -Path "$TestRoot\launcher", "$TestRoot\game", "$TestRoot\xdg_data", "$TestRoot\xdg_config", "$TestRoot\trash", "$TestRoot\desktop" -Force | Out-Null
     $env:HORIZON_LAUNCHER_HOME = "$TestRoot\launcher"
     $env:HORIZON_HOME = "$TestRoot\game"
     $env:XDG_DATA_HOME = "$TestRoot\xdg_data"
     $env:XDG_CONFIG_HOME = "$TestRoot\xdg_config"
     $env:HORIZON_LAUNCHER_TRASH = "$TestRoot\trash"
     $env:HORIZON_LAUNCHER_DESKTOP = "$TestRoot\desktop"
     ```
  3. Microsoft アカウントの初回サインイン（オーナー確認ゲート）から検証する場合は、対象データフォルダーに `accounts.json` が存在しないこと（またはランチャーの「設定 > アカウント」からサインアウト済みであること）を確認する。
- **期待する結果**:
  - ランチャーデータフォルダーおよびゲームデータフォルダーが空の状態で開始でき、既存環境の設定やトークンが混入しない。
- **確かめる所**:
  - エクスプローラーまたは PowerShell で `$env:HORIZON_LAUNCHER_HOME`（通常時は `%APPDATA%\horizon-launcher`）と `$env:HORIZON_HOME`（通常時は `%APPDATA%\horizon`）の中身が空であり、`settings.json`・`accounts.json`・`yoake-token`・`yoake-account.json` が存在しないこと。

## 2. ランチャーの初回起動〜サインイン〜バージョンの導入〜ゲーム起動

### ステップ 2-1: Windows インストーラー（セットアップ画面）での導入

- **手順**:
  1. `horizon-launcher-setup.exe`（または `horizon-launcher.exe install`）を起動する。
  2. セットアップウィンドウでインストール先（既定: `%LOCALAPPDATA%\Programs\Horizon Launcher`）と「Desktop shortcut」スイッチ（既定: オン）を確認し、「Install」をクリックする。
  3. 「Horizon Launcher is installed.」と表示されたら「Launch Horizon」をクリックする。
- **期待する結果**:
  - 管理者権限（UAC 昇格）なしでインストールが完了し、ショートカットとレジストリが登録され、ランチャー本体が起動する。
- **確かめる所**:
  - セットアップ画面の進捗表示（「Copying files」→「Making shortcuts」→「Registering with Windows」→「Horizon Launcher is installed.」）。
  - ファイル:
    - `%LOCALAPPDATA%\Programs\Horizon Launcher\horizon-launcher.exe`
    - スタートメニュー: `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Horizon Launcher.lnk`
    - デスクトップ: `Horizon Launcher.lnk`
  - レジストリ:
    - `HKCU\Software\Horizon\Launcher`（`InstallDir`）
    - `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\HorizonLauncher`（`DisplayName`, `DisplayVersion`, `UninstallString` 等）

### ステップ 2-2: ランチャーの初回起動とオープニング表示

- **手順**:
  1. ステップ 1-2 のクリーンな状態でランチャーを起動する。
  2. 起動直後のオープニングアニメーション（`YOAKE` のワードマーク表示）を確認する（クリックまたはキー入力でスキップできることも確認する）。
- **期待する結果**:
  - 1180×760 のランチャーウィンドウが開き、`YOAKE` ワードマークのオープニングが表示された後、メイン画面（または Microsoft アカウントのサインイン案内シート）に遷移する。
  - Yoake ビルドではデータ収集（テレメトリ）の同意シートが表示されず、ゲームのテレメトリ送信が常時オフ（`HORIZON_TELEMETRY_URL=off`）になっている。
- **確かめる所**:
  - 画面: 起動時の `YOAKE` ワードマーク表示と、ウィンドウタイトルバーの `Yoake Launcher`。
  - 設定画面: 「設定 > ランチャー」に「起動アニメーションを表示」（`Show the opening`）のトグルがあること。また、通常の Horizon にあるデータ収集（`Data collection`）セクションが Yoake ブランドでは非表示であり、データ収集同意ポップアップが出ないこと。

### ステップ 2-3: Microsoft アカウントでのサインイン（オーナー確認ゲート）

- **手順**:
  1. Microsoft アカウント未サインイン状態で表示されるオーナー確認画面（「プレイするには、Minecraft: Java Editionを所有するMicrosoftアカウントでサインインしてください」/ `Sign in to play`）、またはホーム画面で「プレイ」を押したときに開くシートで、「Microsoftでサインイン」（`Sign in with Microsoft`）をクリックする。
  2. （任意・異常系確認）もし Minecraft: Java Edition を**所有していない** Microsoft アカウントがある場合は、先にそのアカウントでブラウザ認証を行い、プレイが拒否されることを確認する。
  3. 画面に表示された 8 桁前後のコード（`user_code`）を「コードをコピー」（`Copy code`）でコピーし、「リンクを開く」（`Open link`）をクリックしてブラウザで `microsoft.com/link`（または `login.live.com`）を開く。
  4. コードを入力し、**Minecraft: Java Edition を所有している Microsoft アカウント**でサインインを完了する。
- **期待する結果**:
  - 認証中、ランチャーに「Microsoftのサインインを更新中…」→「Xbox Liveにサインイン中…」→「Minecraftセッションを取得中…」→「Minecraftの所有状況を確認中…」→「Minecraftプロフィールを読み込み中…」と状態が表示される。
  - Java Edition 未所有アカウントの場合はエラー（「minecraft.netでMinecraft: Java Editionの所有状況とプロフィールを確認してください。」/ `OwnershipRequired`）となり、ゲームを起動できない。
  - Java Edition 所有アカウントでサインインすると、オーナー確認シートが自動で閉じ、上部バーおよび「設定 > アカウント」にプレイヤー名と「オンラインプレイの準備完了」（`Ready for online play`）が表示される。
- **確かめる所**:
  - 画面:
    - オーナー確認シート（`id="owner-gate"`）のコード表示・コピー動作。
    - サインイン完了後の上部バー右側のアカウント表示、および「設定 > アカウント」（`Settings > Account`）の「Microsoft アカウント · プレイ中」（`Microsoft account · plays`）・「オンラインプレイの準備完了」（`Ready for online play`）。
  - ファイル:
    - `<ランチャーデータフォルダー>\accounts.json` が作成され、Minecraft のプレイヤー名・UUID が記録されていること（アクセストークン・リフレッシュトークン自体は OS のキーチェーン／資格情報マネージャーに保存され、`accounts.json` に平文トークンが書かれていないこと）。
    - `<ランチャーデータフォルダー>\settings.json` に `"owner_notice_seen": true` が保存されること。

### ステップ 2-4: Yoake ポータルへのサインイン（メンバー／フレンド招待）

- **手順**:
  1. 上部ナビゲーションバーの「Yoake」タブをクリックして Yoake ページを開く。
  2. **【メンバーの場合（Discord サインイン）】**:
     - 「メンバー」（`Members`）欄の「Discordでログイン」（`Sign in with Discord`）をクリックする。
     - 画面に「コード XXXX-XXXX」（`Code {code}`）が表示され、ブラウザでポータルの承認ページ（`<YOAKE_PORTAL_URL>/launcher?code=...`）が開くので、ブラウザ側でログインを許可する。
  3. **【フレンドの場合（招待コード参加）】**:
     - 「フレンド」（`Friends`）欄に、メンバーから受け取った招待コード（`YK-XXXX-XXXX`）と「あなたの名前」（`Your name`）を入力し、「招待コードで参加」（`Join with the invite`）をクリックする。
     - （異常系確認）誤った招待コード（例: `YK-0000-0000`）を入力して「招待コードで参加」を押し、「招待コードが違います。」（`That invite code is wrong.`）と表示されることも確認する。
- **期待する結果**:
  - サインインが完了すると「ログインしました。」（`Signed in.`）と表示される。
  - メンバーの場合はアカウント名とともに「メンバーとしてログイン中」（`Signed in as a member`）・「Discordのメンバーである間は有効です。」と表示される。
  - フレンドの場合は「フレンドとしてログイン中」（`Signed in as a friend`）・「`{日付}` まで有効です（遊んでいる間は自動で延長されます）。」と表示される。
  - Yoake ページの「パック」（`Packs`）一覧が読み込まれる。
- **確かめる所**:
  - 画面: 「Yoake」ページのサインイン状態カード（「メンバーとしてログイン中」または「フレンドとしてログイン中」）と「サインアウト」（`Sign out`）ボタン。
  - ファイルと権限:
    - `<ランチャーデータフォルダー>\yoake-token` と `<ランチャーデータフォルダー>\yoake-account.json` が作成されていること。
    - `yoake-account.json` をテキストエディタで開き、`name`・`role`（`"member"` または `"friend"`）・`expires_at` のみが入っており、**シークレットトークン文字列が含まれていない**こと。
    - PowerShell で `icacls "$env:APPDATA\horizon-launcher\yoake-token"` および `icacls "$env:APPDATA\horizon-launcher\yoake-account.json"`（一時フォルダー使用時は該当パス）を実行し、現在のユーザーの SID のみにフルコントロール `(F)` が付与され、継承が削除されていること（Unix 系ではパーミッション `0600`）。

### ステップ 2-5: バージョン／Yoake パックの導入とリソース準備（Prepare）

- **手順**:
  1. **Yoake パックを導入する場合**:
     - 「Yoake」ページの「パック」（`Packs`）一覧で、対象のパックの「インストール」（`Install`）をクリックする。
  2. **単体バージョンを導入する場合**:
     - 「バージョン」（`Versions`）ページ（またはホーム画面の「バージョンを選択」/ `Choose a version`）を開き、対象のリリースバージョンの「インストール」（`Install`）をクリックする。
  3. 初回導入時または「プレイ」（`Play`）/「ダウンロードして準備」（`Download and prepare`）クリック時に、Mojang からの Minecraft 26.3 ファイルおよび Java ランタイムのダウンロードとリソース準備（Prepare）が自動実行されるのを待つ（既存の `.minecraft` がある場合は「自分のインストールから」/ `From my install` も選択可能）。
- **期待する結果**:
  - パックまたはバージョンがダウンロード・検証され、続いてリソース準備の進捗（「ゲームファイル」`Game files` → 「Java」 → 「サウンド」`Sounds` → 「準備」`Prepare`）が進み、「準備完了」（`Ready` / `Prepared for Minecraft 26.3`）になる。
- **確かめる所**:
  - 画面:
    - ホーム画面または Yoake ページの進捗バー（「MojangからMinecraft 26.3をダウンロード中 · {done}/{total} ファイル」→「準備中…」→「準備完了」）。
  - ファイル／フォルダー:
    - 単体バージョン導入時: `<ランチャーデータフォルダー>\versions\<tag>\.installed`、実行ファイル `horizon-client.exe`、および `<ランチャーデータフォルダー>\versions\<tag>\.local\horizon-client\26.3\horizon-resources.json` と `assets\minecraft\sounds.json`。
    - Yoake パック導入時:
      - `<ランチャーデータフォルダー>\yoake-cache\objects\`（ダウンロードされたオブジェクトキャッシュ）
      - `<ランチャーデータフォルダー>\yoake-bases\<base_version>\horizon-client.exe` および `.local\horizon-client\26.3\horizon-resources.json`
      - `<ランチャーデータフォルダー>\instances\<id>\yoake-pack.json` および `horizon-mods.txt`
    - Mojang ダウンロードキャッシュ: `<ランチャーデータフォルダー>\minecraft\` および `<ランチャーデータフォルダー>\server-jars\26.3.jar`。

### ステップ 2-6: ゲームの起動とシングルプレイワールドの動作確認

- **手順**:

## 3. 日本語と英語の切り替え（ランチャーとゲーム）

## 4. MOD（`.yak`）の取り込み、Wasm 専用スイッチ（`YOAKE_WASM_UNSIGNED` / ランチャー開発者オプション）、開発者モード

> **【前提：Wasm 専用スイッチを含むビルドであること】**:
> - 設計（`.lane/ref/yoake-wasm-dev.md`、ブランチ `origin/yoake/wasm-dev-switch` の `docs/yoake-wasm-dev.md`）では、署名なし `[wasm]` を読み込むスイッチは **`YOAKE_WASM_UNSIGNED=1`**（Wasm 専用。ネイティブ DLL は許可しない）です。ランチャーの開発者向けオプションには、これに対応する **「自分の WASM MOD をテスト」/ `Test your own WASM mods`** のトグルがあります（設定キー `dev_unsigned_wasm`、トグル `id="dev-unsigned-wasm"`、確認ボタン `confirm-unsigned-wasm` / `cancel-unsigned-wasm`）。
> - 旧来の **「自作の DLL MOD を試す（開発者モード）」/ `Test your own DLL mods (developer mode)`**（設定キー `dev_unsigned_dll`、`id="dev-unsigned-dll"`、確認ボタン `confirm-unsigned-dll` / `cancel-unsigned-dll`）は別トグルとして残り、環境変数 `YOAKE_DLL_MODS_UNSIGNED=1` を設定します。これは **未署名ネイティブ DLL も許可する上位互換のスイッチ**で、Wasm の開発機能も有効になります（ネイティブ DLL の作業専用）。
> - このリポジトリの現在のブランチ（`yoake/release-plan` の土台）のランチャーには WASM トグルがまだありません（`origin/yoake/wasm-dev-switch` は未マージ）。**テスト対象の 1.0 ビルドにこのブランチが入っていることを必ず確認してください**（入っていなければ 4-1 の WASM トグルの項目と 4-4 のトグル経路は実施不可。**【要確認】**）。
> - MOD ガイド 03・07（`.lane/ref/guides/guide-publish/docs/guide-ja/`）は、まだ「DLL トグルしかない」前提で書かれています（ガイド側の更新待ち）。本書の手順とガイドが食い違う場合は、本書とブランチ側の `docs/yoake-wasm-dev.md` を優先し、食い違いを記録してください。

### ステップ 4-1: 開発者向けオプションの解放と、2 つのトグル（WASM／DLL）のオン／オフ操作

- **手順**:
  1. ランチャー左サイドバー最下部のバージョン表記「ランチャー x.y.z」（`Launcher x.y.z`）を **7 回連続でクリック**する。
  2. 自動的に「設定 > ランチャー」ページが開き、最下部に「Developer options」セクション（見出しは日本語 UI でも英語のまま）が現れることを確認する。
  3. **WASM トグル**: 「自分の WASM MOD をテスト」（`Test your own WASM mods`、`id="dev-unsigned-wasm"`）をクリックし、警告文（「自分の未署名 .yak MOD のテスト用です。WASM はサンドボックス内で実行されますが、MOD が宣言した権限（サーバーの service.commands を含む）が適用されます。他の人の MOD には使わないでください。」）と、ボタン「オンにする」（`Turn on`）／「やめる」（`Cancel activation`）が出ることを確認する。まず「やめる」でオンにならないことを確認し、もう一度トグルをクリックして「オンにする」を押す。
  4. 左サイドバー最下部に「開発者モード」（`Developer mode`）バッジが出ることを確認する。トグルをもう一度クリックすると**確認なしで**オフに戻り、バッジが消えることも確認する（WASM と DLL の**どちらか一方でも**オンならバッジが出る）。
  5. **DLL トグル**: 「自作の DLL MOD を試す（開発者モード）」（`id="dev-unsigned-dll"`）も同じ手順（警告文＋「オンにする」／「やめる」）で動くことを確認し、確認後はオフに戻しておく。2 つのトグルが**互いに独立**していること（WASM だけオン、DLL だけオン、が可能）を確認する。
- **期待する結果**:
  - 7 回クリックするまでは開発者向けオプションは隠れている（どちらかのトグルがオンの間は、最初から表示されたままになる）。
  - どちらのトグルも、確認の「オンにする」を押したときだけ有効化される。
  - WASM トグルがオンのとき、ランチャーから起動したゲーム（およびサーバー）にだけ環境変数 `YOAKE_WASM_UNSIGNED=1` が付く。DLL トグルは `YOAKE_DLL_MODS_UNSIGNED=1` を付ける。オフのときはランチャーが起動環境からその変数を**取り除く**。
- **確かめる所**:
  - 画面: サイドバー下部「ランチャー {version}」横の「開発者モード」バッジ、「Developer options」内の 2 つのトグルと確認ボタン。
  - ファイル: `<ランチャーデータフォルダー>\settings.json` に、WASM オン時 `"dev_unsigned_wasm": true`、DLL オン時 `"dev_unsigned_dll": true`（オフ時はキーなし）。
  - 環境変数（任意）: ゲーム起動中に `Get-CimInstance Win32_Process` では環境変数は見えないため、ゲームログの `wasm: ... engine started`（4-4）で間接的に確認する。**【要確認】**: 環境変数そのものを確認する簡便な手段。

### ステップ 4-2: 署名付き `.yak` MOD の取り込みと通常モードでの実行（正常系）

- **手順**:
  1. 開発者向けオプションの WASM・DLL トグルが**どちらもオフ**（かつ環境変数 `YOAKE_WASM_UNSIGNED` / `YOAKE_DLL_MODS_UNSIGNED` が未設定）であることを確認する。
  2. インストール済みの Yoake パックのインスタンスを選択し、上部バーの「Mods」ページを開く。
  3. 「Yoake MOD」（`Yoake mods`）セクションで、以下のいずれか（または両方）を行う:
     - **カタログから導入**: 「Yoake カタログ」（`Yoake catalog`）に表示されている公式署名付き MOD の「インストール」（`Install`）をクリックする。
     - **ローカルファイルの取り込み**: Yoake の信頼された公開鍵（`YOAKE_COMPILED_PUBLIC_KEYS`）で正しく署名された `.yak` ファイルを、「.yak ファイルを追加…」（`Add a .yak file…`）またはドラッグ＆ドロップ領域（`id="yak-drop"`）にドロップする。
  4. 「MOD の変更内容を確認」（`Review mod changes`）パネルで変更内容を確認し、「確認」（`Confirm`）をクリックする。
  5. ゲームを起動し、MOD が読み込まれて動作することを確認する。
- **期待する結果**:
  - 未署名警告が出ずにインストールが完了し、「インストール済み」（`Installed`）一覧に MOD が表示される。
  - ゲーム起動時、署名検証に通過して MOD（Wasm / データ / アセット）が正常に読み込まれる。
- **確かめる所**:
  - 画面: 「Mods」ページの「Yoake MOD」一覧に該当 MOD とバージョンが表示されていること。
  - ファイル／フォルダー:
    - `<インスタンスの home>\yoake-mods\<id>\<version>\` にターゲット別の展開ファイル（`yak.toml`、`SIGNATURE`、`bin/wasm/<id>.wasm` 等）が配置されていること。
    - `<インスタンスの home>\yoake-mods\.cache\<sha256>.yak` と `<インスタンスの home>\yoake-mods\.cache\installed.json` が作成されていること。
    - `<インスタンスの home>\yoake-mods.txt` に `<id>\t<version>` が 1 行ずつ記録されていること。
  - ゲームログ: `<インスタンスの home>\logs\latest.log` に `wasm: <N> mod(s), engine started`（Wasm MOD の場合）が出力され、拒否ログ（`refused`）が出ていないこと。

### ステップ 4-3: 署名なし `[wasm]` `.yak` の通常モードでの拒否確認

- **手順**:
  1. 開発者向けオプションの **WASM・DLL 両方のトグルをオフ**にし、環境変数 `YOAKE_WASM_UNSIGNED` および `YOAKE_DLL_MODS_UNSIGNED` が設定されていない状態にする。
  2. `SIGNATURE` ファイルを含まない、`[wasm]` セクション（`[bin]` なし）を持つ自作の未署名 `.yak`（例: `yoake build` で生成した `dist/<id>-<version>.yak`）を用意する。
  3. ランチャーの「Mods」ページで「.yak ファイルを追加…」からこの未署名 `.yak` を選び、「MOD の変更内容を確認」パネルに警告（「署名のないデータ専用 MOD です。配布元を信頼できる場合のみインストールしてください。」/ `Unsigned data-only mod. Install only if you trust its source.`）と「署名なし」（`Unsigned .yak`）バッジが表示されることを確認して「確認」（`Confirm`）を押す。
  4. そのまま通常モードでゲームを起動する。
- **期待する結果**:
  - パッケージ内にデータやリソースがあればファイル自体は展開されるが、**ゲーム本体は署名のない Wasm モジュールの実行を拒否**し、Wasm コードは一切実行されない。
- **確かめる所**:
  - 画面:
    - ランチャー「Mods」ページの該当 MOD 行に「署名なし」（`Unsigned .yak`）バッジが表示されること。
    - ゲーム内に、未署名 Wasm モジュールが拒否された旨の通知が出るか（**【要確認】**: 資料にはログ `YAK <id> wasm module refused` しか定義がなく、画面通知の有無・文言は不明。出なくても NG とはしない）。
  - ゲームログ: `<インスタンスの home>\logs\latest.log` に **`YAK <id> wasm module refused`** が出力され、他の署名付き Wasm MOD がなければ **`wasm: no mods (engine not started)`** となること。

### ステップ 4-4: `YOAKE_WASM_UNSIGNED=1`（WASM トグル）での署名なし `[wasm]` 読み込みとホットリロード

- **手順**:
  1. ステップ 4-3 の署名なし `[wasm]` `.yak`（`[bin]` なし・`SIGNATURE` なし）が導入済みであることを確認する。
  2. ランチャーの **WASM トグル（4-1）をオン**にしてから、ランチャーからゲームを起動する。（ランチャーを通さず直接起動する場合は、**同じ PowerShell ウィンドウ内だけ**で `$env:YOAKE_WASM_UNSIGNED='1'` を設定してゲームを起動する。`setx` や OS の環境変数への登録はしない。）
  3. 4-3 で拒否された `.yak` が今回は読み込まれ、動作することを確認する。
  4. （ホットリロード・`client-mod` の MOD のみ）ゲームを起動したまま、MOD のソースを変更して `yoake build` し、展開先 `<インスタンスの home>\yoake-mods\<id>\<version>\bin\wasm\<id>.wasm` を上書きして、書き込み後に約 1 秒以上待つ。
  5. （開発フォルダー経由・任意）ランチャーを通さず、同じ PowerShell ウィンドウで `$env:YOAKE_WASM_UNSIGNED='1'` と `$env:YOAKE_WASM_DEV_DIR='<フォルダーのパス>'` を設定してゲームを直接起動し、フォルダー内の `<id>.wasm` が `.yak` なしで読み込まれる（MOD ID には `dev-` が付く）ことを確認する。プロジェクトフォルダーで `yoake dev` を実行すると、`client-mod` の場合はビルドした `.wasm` がそのフォルダーへコピーされる。`client-full` / `server-full` の MOD は `raw Wasm hot reload only supports client-mod; not installed` となり、`.yak` 経由（`yoake pack`→取り込み）で試す。
  6. （DLL トグルとの違い・任意）WASM トグルをオフ、DLL トグルをオンにして同じことが起きる（Wasm 開発機能も有効になる＝上位互換）ことを確認する。確認後は両方オフに戻す。
- **期待する結果**:
  - `YOAKE_WASM_UNSIGNED=1` のとき、署名のない `[wasm]`（`[bin]` を持たないもの）が読み込まれ、`wasm: 1 mod(s), engine started` となる。ネイティブ DLL は読み込まれない。
  - ホットリロードは `client-mod` のみ。ゲーム実行中に未署名のインストール済み `.wasm`（または `YOAKE_WASM_DEV_DIR` 内の `.wasm`）を更新すると、1 秒間隔のポーリングで「書き込みが終わって 1 回分のポーリングの間変化がなかった」時点で新しいインスタンスが作られ、次のフレームまたはティックで差し替わる。壊れた `.wasm` を置いた場合は直前の正常なインスタンスが維持され、ログに警告が 1 行出る。
  - 開発フォルダーの `.wasm` は**ゲーム起動時に見つかったものだけ**が対象（起動後に新しく置いたファイルは、再起動するまで読まれない）。
  - `SIGNATURE` が付いている `.yak` は、スイッチがオンでも署名検証が必須（4-5 のケース C）。
- **確かめる所**:
  - ゲームログ（`<インスタンスの home>\logs\latest.log`）:
    - 起動時に `wasm: 1 mod(s), engine started` が出力されること（MOD が 1 つも無いときは `wasm: no mods (engine not started)`）。
    - `.wasm` 更新時のホットリロード成功・失敗の警告ログ（**【要確認】**: ログ文言そのもの。資料には「警告が 1 行出る」としか書かれていない）。
  - ゲーム画面: MOD の変更内容が再起動なしで反映されること。
  - 4-1 でトグルをオフに戻した後、再起動したゲームで 4-3 と同じ拒否（`YAK <id> wasm module refused`）に戻ること。

### ステップ 4-5: 拒否されなければならない不正・危険なパッケージの検証（必須拒否チェック）

以下の **A〜E** のケースを順番に試し、すべて確実に**拒否**されることを確認します。

- **手順**:
  1. **ケース A（通常モードでの未署名ネイティブ `[bin]` / DLL `.yak`）**:
     - WASM・DLL 両方のトグルを**オフ**にした状態で、`[bin]`（DLL 等のネイティブバイナリ）を含み `SIGNATURE` がない `.yak` をランチャーの「.yak ファイルを追加…」から取り込もうとする。
  2. **ケース B（`YOAKE_WASM_UNSIGNED=1` のみでの未署名ネイティブ `[bin]` / DLL `.yak`）**:
     - `YOAKE_DLL_MODS_UNSIGNED` を設定せず、`YOAKE_WASM_UNSIGNED=1` のみを設定した状態で、未署名の `[bin]`（DLL）入り `.yak` を `<インスタンスの home>\yoake-mods\` に配置してゲームを起動する。
  3. **ケース C（壊れた `SIGNATURE`・未知の鍵による署名・署名後のファイル改ざん）**:
     - **WASM／DLL のトグルがオン（または `YOAKE_WASM_UNSIGNED=1`）の状態であっても**、`SIGNATURE` ファイルが存在するのに中身が壊れている／信頼された公開鍵（`YOAKE_COMPILED_PUBLIC_KEYS`）以外の鍵で署名されている／署名後に `.wasm` や `yak.toml` を 1 バイト書き換えた `.yak` を取り込み・起動しようとする。
  4. **ケース D（マニフェスト・アーカイブ構造違反）**:
     - 以下の不正な `.yak` を取り込もうとする:
       - `[bin]` と `[wasm]` の両方を同時に宣言した `yak.toml`
       - 未宣言のルートフォルダーや未宣言のファイルを含むアーカイブ、またはパストラバーサル（`..`、バックスラッシュ `\`、シンボリックリンク）を含むアーカイブ
       - `[service]` にシークレット名（`token`、`password`、`secret`、`api_key` 等）を含む `yak.toml`
       - 既にキャッシュされている同一 `(id, version)` と異なる SHA-256 を持つ別アーカイブ
  5. **ケース E（Wasm インポート違反・Mixin 違反）**:
     - `wasi:sockets/*` 等の許可されていない WASI インターフェースをインポートする `.wasm` を読み込ませる。
     - Mixin（`interface = "1.1"`, `world = "inject-mod"`）で、`path#signature_hash` のハッシュが不一致のもの、または同じフック箇所（site + side）に 2 つの MOD が同時に `overwrite` を登録したもの、`service.commands` / `service.chat` 権限なしでコマンド／チャットフックを登録したものを読み込ませる。
- **期待する結果**:
  - **ケース A**: ランチャーが「プログラムを含む .yak には有効な Yoake の署名が必要です。」（`A program .yak needs a valid Yoake signature.`）として取り込みを拒否する。
  - **ケース B**: `YOAKE_WASM_UNSIGNED=1` は Wasm 専用であり、ネイティブ DLL（`[bin]`）は一切読み込まれず拒否される。
  - **ケース C**: `SIGNATURE` ファイルが存在する場合、開発者モードや `YOAKE_WASM_UNSIGNED=1` の有無にかかわらず署名検証およびファイルハッシュ照合が強制され、不一致のパッケージはランチャー・ゲーム双方で拒否される（`SIGNATURE` 内の自己申告 `signer` 鍵がそのまま信頼されることは決してない）。
  - **ケース D**: ランチャー（およびゲームのローダー）がマニフェスト／アーカイブ検証エラーで拒否し、展開しない（同一 `id, version` で別ハッシュの場合は `A different archive already uses this mod version` で拒否）。
  - **ケース E**: ゲーム起動時の Wasm リンカ／Mixin 登録検証で当該 MOD が拒否（またはトラップによる該当 MOD 単体の自動無効化）され、ゲーム本体はクラッシュせずバニラ動作を保つ。
- **確かめる所**:
  - 画面: ランチャー「Mods」ページの赤字エラーバナー表示（「プログラムを含む .yak には有効な Yoake の署名が必要です。」等）。
  - ゲームログ（`<インスタンスの home>\logs\latest.log`）: 各不正 MOD に対する拒否ログ（`refused` / 署名エラー / インポートエラー / Mixin 競合・ハッシュ不一致エラー）が出力され、該当 MOD が有効化されていないこと。

## 5. フレンド

### ステップ 5-1: ポータル側でフレンド機能が有効化される前の「まだ使えません」表示の確認

- **手順**:
  1. フレンド機能（Social API `/api/social/v1/me`）がまだ有効になっていないポータル環境（HTTP `404` / `405` / `410` を返す状態、またはポータル未設定ビルド）で、ランチャー上部の「フレンド」（`Friends`）ページを開く。
  2. 表示されるメッセージと「再試行」（`Try again`）ボタンを確認する。
  3. そのままゲームを起動し、ポーズメニューの「Play with Friends」→「Start Sharing」から 1 回限りの招待コード（52 文字または 79 文字の Base32 コード）を発行できることを確認する。
- **期待する結果**:
  - ランチャーの「フレンド」ページにはクラッシュや生の HTTP エラーではなく、「フレンド機能はまだ使えません。」（`Friends are not available yet.`）・「ポータル側でまだ有効になっていません。有効になるとここに表示されます。」（`The portal has not turned them on. They will show up here once it does.`）と「再試行」（`Try again`）ボタンが表示される。
  - ポータルのフレンド機能が無効な状態でも、ゲーム内の招待コード方式（「Play with Friends」）は独立して動作する。
- **確かめる所**:
  - 画面:
    - ランチャー「フレンド」ページの「フレンド機能はまだ使えません。」カードと「再試行」（`id="friends-retry"`）ボタン。
    - （未サインイン状態で「フレンド」ページを開いた場合は、「サインインしていません。」/ `You are not signed in.` と「Yoake を開く」/ `Open Yoake` ボタンが表示されることも併せて確認する）。

### ステップ 5-2: フレンドコードの表示・コピー・再発行（ローテーション）

- **手順**:
  1. ポータルでフレンド機能が有効な状態で、PC 1（アカウント A）と PC 2（アカウント B）の両方で Yoake にサインインし、「フレンド」（`Friends`）ページの「フレンド」（`Friends`）タブを開く。
  2. 「あなたのフレンドコード」（`Your friend code`）に `YKF-XXXX-XXXX` 形式（紛らわしい `0, 1, I, O` を含まない英数字）のコードが表示されていることを確認する。
  3. 「コピー」（`Copy`、`id="friends-copy-code"`）をクリックし、ボタン表記が約 2 秒間「コピーしました」（`Copied`）に変わり、クリップボードに `YKF-XXXX-XXXX` がコピーされることを確認する。
  4. 古いフレンドコードをメモしたうえで、「新しいコード」（`New code`）をクリックする。
  5. 2 段階確認でボタンが「もう一度押すと入れ替えます」（`Click again to replace it`）とキャンセル「×」ボタンに変わることを確認する（400ms 以内の誤連打防止ガードがあり、5 秒放置または「×」でキャンセルされることも確認する）。
  6. もう一度「もう一度押すと入れ替えます」をクリックしてコードを再発行する。
- **期待する結果**:
  - 新しい `YKF-XXXX-XXXX` コードに置き換わり、「フレンドコードを入れ替えました。古いコードは使えなくなりました。」（`Your friend code was replaced. The old one no longer works.`）と表示される。
  - PC 2 から古いコード宛てにフレンドリクエストを送っても「そのフレンドコードの人は見つかりません。」（`No one has that friend code.`）となり拒否される。
- **確かめる所**:
  - 画面: 「フレンド > フレンド」タブの「あなたのフレンドコード」欄、「コピー」→「コピーしました」の変化、「新しいコード」→「もう一度押すと入れ替えます」の 2 段階確認と完了メッセージ。

### ステップ 5-3: フレンドリクエストの送信・取り消し・辞退・承認

- **手順**:
  1. PC 2（アカウント B）で「フレンド > リクエスト」（`Requests`）タブを開く。
  2. 入力欄「フレンドコード (YKF-XXXX-XXXX)」に不正な文字列（例: `INVALID-123`）を入力して「リクエストを送る」（`Send request`）を押し、バリデーションエラー（「そのフレンドコードは正しくないようです。フレンドコードは YKF-ABCD-2345 の形です。」）が表示されることを確認する。
  3. PC 1（アカウント A）の現在のフレンドコードを入力（小文字やハイフンなし・前後の空白ありでも正規化されて通ることを確認）し、「リクエストを送る」をクリックする。
  4. PC 2 の「送信済み · 1」（`Sent · 1`）に表示されたリクエストで一度「リクエストを取り消す」（`Cancel request`）をクリックし、「リクエストを取り消しました。」となることを確認する。
  5. 再度 PC 2 から PC 1 へリクエストを送り、PC 1 の「フレンド > リクエスト」タブの「受信 · 1」（`Incoming · 1`）に届くことを確認する（必要に応じて右上の更新ボタンを押す）。
  6. （任意）一度「断る」（`Decline`）を押して「リクエストを断りました。」となることを確認した後、再度 PC 2 からリクエストを送り、今度は PC 1 で「承認」（`Accept`）をクリックする。
- **期待する結果**:
  - PC 1 で「承認」を押すと「フレンドになりました。」（`You are friends now.`）と表示され、PC 1・PC 2 双方の「フレンド」タブの一覧に相手が表示される（「メンバー · {日付} からフレンド」または「ゲスト · {日付} からフレンド」）。
- **確かめる所**:
  - 画面:
    - 「フレンド > リクエスト」タブの「受信 · {count}」と「送信済み · {count}」の件数バッジおよび通知メッセージ。
    - 「フレンド > フレンド」タブの一覧に相手アカウントの表示名・種別（`メンバー` / `ゲスト`）・フレンド開始日が表示されていること。

### ステップ 5-4: グループの作成・招待コードの発行と参加・取り消し

- **手順**:
  1. PC 1（アカウント A）で「フレンド > グループ」（`Groups`）タブを開く。
  2. 「グループ名」（`Group name`）に 1〜40 文字の名前（例: `Yoake テスト班`）を入力し、「グループを作る」（`Create group`）をクリックする。
  3. 自動的に開くグループ詳細画面で、自分の役割が「オーナー」（`Owner`）であり、「招待」（`Invites`）セクションが表示されていることを確認する。
  4. 使用回数ボタン（既定 `5 回まで`、クリックするごとに `1 回まで` → `5 回まで` → `10 回まで` → `50 回まで` と循環）と有効日数ボタン（既定 `7 日間`、クリックするごとに `1 日間` → `7 日間` → `14 日間` → `30 日間` と循環）を選び、「招待を作る」（`Create invite`）をクリックする。
  5. 「新しい招待コード」（`New invite code`）として `YKG-XXXX-XXXX` が表示され、「表示されるのは今回だけです。公開のチャットではなく、個別に送ってください。」（`Shown only once. Send it privately, not in a public chat.`）と案内されることを確認し、「コピー」（`Copy`）でコードをコピーする。
  6. 一度グループ一覧（「← グループ」）に戻ってから再度同じグループを開き、先ほどの招待コード文字列自体（`YKG-...`）は二度と再表示されず、「有効な招待 1 / 20」（`{used} / {max} 回使用 · {date} まで`）の行だけが表示されることを確認する。
  7. PC 2（アカウント B）で「フレンド > グループ」タブを開き、「招待コード (YKG-XXXX-XXXX)」欄にコピーしたコードを入力して「コードで参加」（`Join with code`）をクリックする。
  8. PC 1 で有効な招待の「取り消す」（`Revoke`）をクリックし、「招待を取り消しました。」（`Invite revoked.`）となることを確認する。
- **期待する結果**:
  - PC 2 がグループに参加でき（「グループに参加しました。」/ `You joined the group.`）、メンバー一覧（「メンバー · 2」）に PC 1（オーナー）と PC 2（メンバー）が表示される。
  - 取り消した招待コードや回数上限に達した招待コードでは「その招待は使えません。コードが違うか、期限切れ・使い切り・取り消し済みの可能性があります。」となり参加できない。
- **確かめる所**:
  - 画面:
    - グループ詳細画面の「オーナー · メンバー 2 / 100 人」表示。
    - 招待コード作成直後の 1 回限りの表示ボックス（`New invite code`）と、画面遷移後にコード平文が消えていること。

### ステップ 5-5: グループのメンバーロール変更・オーナー引き継ぎ・追放（参加禁止）と解除

- **手順**:
  1. PC 1（オーナー）でグループ詳細画面の「メンバー · 2」一覧を見る。
  2. PC 2（メンバー）の行にある「⋯」ボタン（`more-horizontal`）をクリックしてポップオーバーメニューを開き、「管理者にする」（`Make admin`）をクリックする。
  3. PC 2 のロール表示が「管理者」（`Admin`）になり、PC 2 側でも「招待」（`Invites`）セクションが操作可能になることを確認する。
  4. 再度 PC 1 で「⋯」メニューを開き、「メンバーにする」（`Make member`）をクリックして PC 2 を「メンバー」に戻す。
  5. （オーナーの退出不可確認）オーナーである PC 1 には「グループを抜ける」（`Leave group`）ボタンがなく、「グループを削除」（`Delete group`）のみが表示されていることを確認する（API 上もオーナーは引き継ぎまたは削除なしで退出不可）。
  6. （オーナー引き継ぎ確認・PC 2 がゲストではなくメンバーアカウントの場合）「⋯」メニューから「オーナーにする」（`Make owner`）をクリックし、2 段階確認「もう一度押すとグループを引き継ぎます」（`Click again to hand over the group`）を押してオーナーを移譲できることを確認する（確認後、PC 2 から PC 1 へ同じ手順でオーナーを戻す）。
  7. （追放と参加禁止解除）PC 1（オーナー）で PC 2 の行の赤い「追放」（`Kick`）ボタンをクリックし、2 段階確認「もう一度押すと追放して参加禁止にします」（`Click again to kick and ban`）をクリックする。
  8. PC 2 がメンバー一覧から消え、下部の「参加禁止 · 1」（`Banned · 1`）セクションに移動し、PC 2 が招待コードで再参加しようとしても拒否されることを確認する。
  9. PC 1 で「参加禁止 · 1」の PC 2 の行にある「禁止を解除」（`Lift ban`）をクリックし、「禁止を解除しました。」（`Ban lifted.`）となった後、PC 2 が新しい招待コードで再参加できることを確認する。
- **期待する結果**:
  - ロール変更（メンバー ⇄ 管理者、およびメンバーへのオーナー引き継ぎ）が即座に反映される。
  - 追放されたメンバーは自動的に参加禁止（Ban）となり、「禁止を解除」するまで招待コードを使っても再参加できない。
- **確かめる所**:
  - 画面:
    - グループ詳細画面のロール表記（`オーナー` / `管理者` / `メンバー`）、通知メッセージ（「役割を変えました。」、「グループを引き継ぎました。」、「メンバーを追放しました。禁止を解除するまで、再参加はできません。」、「禁止を解除しました。」）。
    - 「参加禁止 · {count}」セクションの表示と「禁止を解除」ボタン。

### ステップ 5-6: ブロックとブロック解除

- **手順**:
  1. PC 1 の「フレンド > フレンド」タブで、PC 2 の行にある赤い「ブロック」（`Block`）ボタンをクリックし、2 段階確認「もう一度押すとブロックします」（`Click again to block`）をクリックする。
  2. PC 1 の「フレンド」一覧から PC 2 が消え、「フレンド > ブロック」（`Blocked`）タブに PC 2（「{日付} にブロック」/ `Blocked {date}`）が表示されることを確認する。
  3. ブロック中、PC 2 から PC 1 のフレンドコード宛てにフレンドリクエストを送っても PC 1 には届かないことを確認する。また、自分が管理していない（オーナーでも管理者でもない）グループではブロックした相手が非表示になることを確認する。
  4. PC 1 の「フレンド > ブロック」タブで PC 2 の「ブロック解除」（`Unblock`）をクリックしてブロックを解除し、次のセクション 6 のために再度フレンドリクエストを送って承認し、フレンド状態に戻しておく。
- **期待する結果**:
  - ブロックするとフレンド関係が解除されて「ブロック」タブに移り、相手からのフレンドリクエストが遮断される。
  - 「ブロック解除」で一覧から消え、再度フレンド申請が可能になる。
- **確かめる所**:
  - 画面: 「フレンド > ブロック」タブの一覧表示、完了通知（「ブロックしました。」/「ブロックを解除しました。」）、および再度フレンド承認した後の「フレンド」一覧。

> - 一方、ゲーム本体（`horizon-client` / `yoake.exe`）が `--yoake-social-handoff <path>` を読み取った後のゲーム内画面遷移や `latest.log` の具体的なログ文言は本リポジトリの参照ソース外（別ブランチ／統合対象）となっているため、ゲーム内の具体的なログ行・画面表記は **【要確認】** として記載しています。
> - **公開前の制約**: 中継（`horizon-relay`）の social 通信は資料上まだ草案で、「ランチャーとゲームはまだ使っていない。ポータル連携とエンドツーエンド暗号化が済むまで、参加できるサービスとして公開しない」とされています（`.lane/ref/relay/yoake-social-ops.md`）。このセクションの「2 台でプレイできる」ことの確認は、ゲーム側・ポータル側の統合が済んだビルドで初めて実施できます（未統合なら 6-1・6-4・6-5 のランチャー側の動作だけを確認し、6-2 のゲーム内の同期は **【要確認】** のまま保留）。
> - 部屋の流れ（設計の要点）: 部屋は 1 人 1 部屋。ホストが「開く」を押すとポータルが部屋（`session_id`、一度だけ返る `host_token`、署名つき開設券、中継の `host:port`）を返し、ランチャーがそれを本人だけ読めるファイルに書いて `--yoake-social-handoff <パス>` だけをゲームへ渡します（トークンや署名はコマンドラインに載りません）。ゲストの「参加」では、ポータルが期限付きの参加証（grant。240 秒有効）を返し、同じ方法でゲームへ渡します。ゲームは読んだらファイルを消し、中継へ直接つなぎます。ランチャーは、ポータルが返した grant が生きている間（230 秒以内）に起動できなかったファイルを渡さずに捨てます。

### ステップ 7-2: `yoake test` による実ゲームエンジン（オフスクリーン）での自動テスト実行

- **手順**:
  1. 環境変数 `YOAKE_GAME` にテスト対象のゲーム実行ファイル（`horizon-client.exe` または `yoake.exe`）のフルパスを設定する（またはコマンドに `--game <パス>` を渡す）。**所要時間に注意**: 1 テストごとに新しいワーカープロセスとワールドを起動するため、Windows のデバッグビルドで 1 テストあたり 90〜100 秒かかることがある（ガイド 06 第 4 節）。テストは絞り、遅い環境では `-- --yoake-test-startup-seconds 600`（起動の猶予。既定 240 秒）や `--timeout-ms`（1 テストの制限。既定 30000）を増やす。
  2. `my-test-mod` ディレクトリで以下のコマンドを実行する（`<リソースパス>` は準備済みの `.local/horizon-client/26.3` フォルダーのパス）:
     ```powershell
     yoake test -- --resources "<リソースパス>"
     ```
  3. 特定のテストだけを実行する `--filter`（テスト名に指定文字列を**含む**ものを実行）も試す:
     ```powershell
     yoake test --filter <テスト名の一部> -- --resources "<リソースパス>"
     ```
     一致するテストが 0 件のときはエラーにならず、終了コード `0`・`"ok": true`・`"notes": ["no test matches the filter"]` で終わる。`tests` 配列が空でないことも見る。
  4. `--keep` オプションを付けて実行し、テスト用の一時ワールドフォルダーが残ることを確認する:
     ```powershell
     yoake test --keep -- --resources "<リソースパス>"
     ```
- **期待する結果**:
  - `yoake test` が Mod 本体のビルドと `yoake check` を行い、続いて `--features tests` 付きで `bin/wasm/<id>-tests.wasm`（WIT ワールド `test-mod`）をビルドし、ゲームを `--offscreen`（ウィンドウなし）で起動して新設のスーパーフラットワールド（シード `0`、`y=-61` 草ブロック・`y=-60` 空気（下の層は `block_at` で読む。高さはガイド 06 のとおり固定しない）、クリエイティブモードのオーナー（名前は固定されない）、時刻 `6000`、晴天、約 2 秒ウォームアップ後に手動ティック進行）で各 `#[yoake_test]` 関数を実行する。
  - 標準エラー出力（`stderr`）に人間向けの進捗 `yoake test: ok   <テスト名> (<ms> ms)` が出力され、標準出力（`stdout`）の最終行に 1 行の JSON レポートが出力され、終了コード `0` で終了する。
  - `--keep` 指定時は一時フォルダーが削除されず、出力 JSON の `"kept"` フィールドにそのパスが記録される。
- **確かめる所**:
  - 標準エラー出力（`stderr`）: `yoake test: ok   <テスト名> (<ms> ms)` の行。
  - 標準出力（`stdout`）の JSON 行:
    - `"ok": true`, `"built": true`, `"checked": true`, `"tests": [{"name": "...", "ok": true, "ms": ...}]`, `"errors": []` となっていること。
  - 終了コード: `$LASTEXITCODE` が `0` であること。
  - `--keep` 指定時: JSON 内の `"kept"` に示された一時フォルダーがディスク上に残っており、中に `logs\latest.log` 等が存在すること。

### ステップ 7-3: アサーション失敗時の検出と 2 クライアント（マルチプレイ）テスト

- **手順**:
  1. `src/lib.rs` の `#[yoake_test]` 関数内で、わざと失敗するアサーション（例: 空気の座標に対して `world.assert_block(BlockPos { x: 0, y: 10, z: 0 }, "minecraft:diamond_block")?;`）を記述し、`yoake test -- --resources "<リソースパス>"` を実行する。
  2. 失敗がレポートされることを確認したら、コードを元に戻す。
  3. 2 クライアントテスト（`world.client(1)` を使うテスト。先に `world.run_ticks(...)` で変更をサーバーに送らせてから `wait_block` / `wait_chat` で待つ）を記述し、以下のコマンドで 2 クライアントモードを実行する（`--clients 2` は `yoake/p10-test-runner` のコミット `bdc976398` 以降が必要。入っていないビルドでは使えない。**【要確認】**: 1.0 ビルドに含まれているか）:
     ```powershell
     yoake test --clients 2 -- --resources "<リソースパス>"
     ```
- **期待する結果**:
  - アサーション失敗時: `stderr` に `yoake test: FAIL <テスト名>` と失敗理由が出力され、`stdout` の JSON で `"ok": false` および `"errors"` 配列にエラー内容が入り、終了コードが **`1`** になる。
  - `--clients 2` 指定時: 1 台目のクライアントのワールドに `127.0.0.1` 経由で 2 台目のクライアント（`TestB`）が接続し、`world.client(1).wait_block(...)` や `world.client(1).chat(...)` / `wait_chat(...)` による 2 クライアント間の同期テストが成功する。
  - 参考: サーバーの `say`・`me`・`msg`・`tellraw @a` は 2 つ目のクライアントのチャットに届く（`test-demo` の例と `docs/yoake-wasm-dev.md` のとおり。以前は `say` が届かなかったが直っている）。クライアント専用 MOD（HUD など）の動作は `yoake test` では確かめられない。
- **確かめる所**:
  - 失敗時: `stderr` の `yoake test: FAIL` 行、`stdout` JSON の `"ok": false`、および `$LASTEXITCODE` が `1` であること。
  - 2 クライアント時: `stdout` JSON の `"ok": true` と、2 クライアントテストケースが `"ok": true` で通過していること。

## 8. ライト／ダーク／システム表示とアクセントカラー

### ステップ 8-1: 外観（ダーク／ライト／システム）の切り替えと OS 連動

  5. Windows の「設定 > 個人用設定 > 色」で OS のモード（ライト／ダーク）を切り替え、ランチャーを再起動しなくてもリアルタイムでランチャーの外観が追従して切り替わることを確認する。

- **期待する結果**:
  - 「ダーク」「ライト」「システム」の 3 つのモードが即座に切り替わり、どのモードでもテキストやボタンの視認性が保たれる。

- **確かめる所**:
  - 画面: 「設定 > ランチャー > 外観」の選択状態、ホーム画面背景の空模様、カード・サイドバー・タイトルバーの配色。

### ステップ 8-2: アクセントカラー（7 色のプリセットスウォッチと連続色相バー）

- **手順**:
  1. 「設定 > ランチャー」（`Settings > Launcher`）の「アクセントカラー」（`Accent colour`）行を確認する。
  2. 7 つの名前付きカラースウォッチ（左から `violet`［既定］、`blue`、`teal`、`green`、`amber`、`red`、`pink`、`id="accent-<色名>"`）を順番にクリックする。
  3. スウォッチの右隣にある連続色相バー（幅 120px の 360° カラースペクトラム）をクリックおよび左右にドラッグし、マウスボタンを離す。
  4. ライトモードとダークモードの両方で、選択したアクセントカラーにおけるプライマリボタン（ホームの「プレイ」ボタン等）の文字コントラストを確認する。

- **期待する結果**:

- **確かめる所**:

## 9. 更新とロールバック

### ステップ 9-1: ランチャー自身のアップデートフィード確認と自己更新（通常配布版）

- **手順**:
  1. 通常配布版（Store 版ではないビルド）で Yoake ポータルにサインインする。
  2. ポータルの `<YOAKE_PORTAL_URL>/yoake/launcher/latest.json` に、現在実行中のランチャーよりも新しい SemVer バージョンが公開されている環境（または更新テスト用の古いバージョンのランチャーバイナリ）を用意する。
  3. ランチャーを起動するか、「Yoake」ページの更新ボタン、または「設定 > このランチャーとライセンス」（`About / licences`）の「アップデートを確認」（`Check for launcher updates`）をクリックする。
  4. 「Yoake」ページ上部に「新しいランチャー ({version}) があります」（`A new launcher ({version}) is available.`）バナーが表示されたら、「アップデート」（`Update launcher`、`id="yoake-launcher-update"`）をクリックする（併せて「ポータルで見る」/ `View on portal` でリリースページが開くことも確認する）。
  5. ダウンロードと署名・ハッシュ検証が完了し、ボタンが「再起動して更新」（`Restart to update`、`id="yoake-launcher-restart"`）に変わったらクリックする。
- **期待する結果**:
  - ランチャーが `yoake/launcher/<version>/SHA256SUMS` と `.sig` を取得し、埋め込み公開鍵とタグ `yoake-launcher-<version>` で Ed25519 署名を検証したうえで、`<ランチャーデータフォルダー>\.launcher-update\download-<pid>-<n>.tmp` に新しい実行ファイルをダウンロードしてサイズと SHA-256 を照合する。
  - 現在の実行ファイルを `<ファイル名>.old-<pid>-<n>` にリネームして新しい実行ファイルを配置し、「再起動して更新」を押すと新しいバージョンのランチャーで再起動する（ゲーム起動中でもゲームは終了させずにランチャーのみ再起動可能）。
  - 再起動時、退避されていた `.old-*` ファイルが自動的に削除される。
- **確かめる所**:
  - 画面:
    - 「Yoake」ページの更新バナー（「新しいランチャー ({version}) があります」→「ランチャーをダウンロードしています…」→「再起動して更新」）。
    - 再起動後の左サイドバー下部「ランチャー {version}」が新しいバージョン番号になっていること。
  - ファイル:
    - 実行ファイルの更新日時・バージョンが新しくなっており、同じフォルダーに `.old-*` ファイルが残っていないこと。
    - （異常系確認）もし `SHA256SUMS.sig` の署名が不正またはハッシュが不一致の場合は、実行ファイルが一切置き換えられずエラーが表示されること。

### ステップ 9-2: バージョン／Yoake パックの更新と前の版へのロールバック

- **手順**:
  1. **Yoake パックの更新**:
     - 旧バージョンのパックがインストールされた状態で、フィード（`current.json` → `indexes/<seq>/index.json`）に新しいバージョンのパックが公開された状態にする。
     - 「Yoake」ページを開き、導入済みパックの行に「`{version}` が出ています（ダウンロード `{size}`）。」（`{version} is out ({size} to download).`）と「アップデート」（`Update`）ボタンが表示されることを確認する。
     - 「アップデート」（`Update`）をクリックして新しいバージョンへ更新する。
  2. **前の版へのロールバック（`前の版に戻す` / `Go back a version`）**:
     - 更新完了後、同じパックの行に「前の版に戻す」（`Go back a version`）ボタンが表示されることを確認する。
     - 「前の版に戻す」をクリックし、1 つ前のバージョンに戻ることを確認する。
  3. **単体ゲームバージョンの切り替え**:
     - 「バージョン」（`Versions`）ページで複数のバージョンをインストールし、「使う」（`Use`）ボタンまたはホーム画面のバージョン選択ドロップダウンから使用するバージョンを切り替えられることを確認する。
- **期待する結果**:
  - パック更新時、フィードの署名（`yoake-index-v1`）とシーケンス番号の巻き戻し防止（`high_water_seq`）が検証され、管理対象ファイルが更新されるとともに、更新前のマニフェストが `<インスタンスの home>\yoake-pack.previous.json` に保存される（ユーザーが書き換えた `DefaultOnCreate` ファイルは保護され、もし `Managed` ファイルを手動変更していた場合は上書きせず「あなたのファイルが邪魔をしています: `{path}`。移動してからもう一度試してください。」と通知される）。
  - 「前の版に戻す」を押すと、`yoake-pack.previous.json` の `rollback_proof` が検証され、キャッシュ（`yoake-cache/objects/`）またはフィードから前のバージョンが復元される。
- **確かめる所**:
  - 画面: 「Yoake」ページのパック行のバージョン表記（「`{instance} · {version}`」）、更新通知、および「前の版に戻す」ボタンの表示・動作。
  - ファイル:
    - `<ランチャーデータフォルダー>\yoake-feeds\<feed_id>.json` に `high_water_seq` が記録されていること。
    - 更新直後に `<インスタンスの home>\yoake-pack.previous.json` が作成され、ロールバック実行後に `<インスタンスの home>\yoake-pack.json` のバージョンが前の版に戻り、`yoake-pack.previous.json` が消費（削除）されること。

### ステップ 9-3: Microsoft Store 版における Store 経由の更新と署名付き同梱エンジンの検証

- **手順**:
  1. Microsoft Store 版パッケージ（`Yoake-<version>-x64.msix`、`YOAKE_DISTRIBUTION=store` ビルド）をインストールし、`YoakeLauncher.exe` を起動する。
  2. 「Yoake」ページおよび「設定 > このランチャーとライセンス」（`Settings > About / licences`）を開く。
  3. ランチャー自身の自己更新ボタン（「アップデートを確認」/ `Check for launcher updates`）が表示されず、代わりに **「Microsoft Store が Yoake を更新します。」**（`The Microsoft Store updates Yoake.`）と表示されることを確認する。
  4. Store 版で Yoake パックを起動する:
     - **ケース A（同梱 `yoake.exe` とフィードのベースバージョン・サイズ・SHA-256 が完全一致する場合）**: ネットワークからエンジンを再ダウンロードせず、`YoakeLauncher.exe` と同じフォルダーにある同梱 `yoake.exe` が使われて起動することを確認する。
     - **ケース B（パックが異なるベースバージョンまたはネイティブ MOD 入りエンジンを要求する場合）**: ランチャーが `yoake-bases/` のキャッシュ／ダウンロード版エンジンにフォールバックし、ログファイルを出力することを確認する。
- **期待する結果**:
  - Store 版ではランチャーの自己更新機能が完全に無効化されており、アプリケーション本体の更新は Microsoft Store（MSIX パッケージ更新）を通じてのみ行われる。
  - 同梱 `yoake.exe` は、署名付きフィードが示すバージョン・バイトサイズ・SHA-256 と一致したときだけ使用される。
- **確かめる所**:
  - 画面: 「Yoake」ページおよび「設定 > このランチャーとライセンス」の「Microsoft Store が Yoake を更新します。」表示、および「アップデートを確認」ボタンが存在しないこと。
  - ログファイル（ケース B のフォールバック発生時）: `<ランチャーデータフォルダー>\logs\yoake-store.log` に `Yoake Store: no matching signed bundled engine for base <version>; ...` が記録されていること。
  - Store 更新（**【要確認】**）: Microsoft Store（またはより新しいバージョンの `.msix` パッケージの上書きインストール）を実行した際、既存の `<ランチャーデータフォルダー>` やワールドデータを維持したまま新しいバージョンに更新されること。

## 10. アンインストール

### ステップ 10-1: 通常アンインストール（「ランチャーのデータも削除する」オフ）で消えるもの・残るもの

- **手順**:
  1. ランチャーが `%LOCALAPPDATA%\Programs\Horizon Launcher\horizon-launcher.exe` にインストールされており、ゲームおよびランチャーを閉じた状態にする。

  3. 「Removes Horizon Launcher from this computer. Your worlds and the game's folder stay.」の説明文を確認し、**「Also delete the launcher's data」のスイッチ（日本語訳なし。インストーラー／アンインストーラー画面は英語表記のまま）をオフ（既定）**のまま「Uninstall」をクリックする。
  4. 「Horizon Launcher was removed.」と表示されたら「Close」をクリックして閉じる。
- **期待する結果**:
  - **削除されるもの**:
    - インストール先フォルダー `%LOCALAPPDATA%\Programs\Horizon Launcher\` とその中の `horizon-launcher.exe`（実行中バイナリは `%TEMP%\horizon-launcher-uninstall-<pid>.exe` に退避され、次回セットアップ／アンインストール時に掃除される）。※もしインストール先フォルダー内にユーザーが手動で置いた無関係なファイルがあった場合は削除されず残され、「These could not be removed:」に一覧表示される。
    - スタートメニューのショートカット `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Horizon Launcher.lnk`
    - デスクトップ上のショートカット（`Horizon Launcher.lnk` およびこのランチャーを指すインスタンスショートカット `*.lnk`）
    - レジストリキー `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\HorizonLauncher` および `HKCU\Software\Horizon\Launcher`（空になった場合は `HKCU\Software\Horizon` も）
  - **残るもの（削除されないもの）**:

- **確かめる所**:
  - エクスプローラー／PowerShell:
    - `%LOCALAPPDATA%\Programs\Horizon Launcher`・スタートメニューショートカット・デスクトップショートカットが**消えている**こと。
    - `Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\HorizonLauncher" -ErrorAction SilentlyContinue` が何も返さないこと。
    - `%APPDATA%\horizon-launcher` と `%APPDATA%\horizon` が**両方ともそのまま残っている**こと。

### ステップ 10-2: データ削除付きアンインストール（「ランチャーのデータも削除する」オン）で消えるもの・残るもの

- **手順**:

- **期待する結果**:

    - ステップ 10-1 で削除されるプログラム本体・ショートカット・レジストリ一式に**加えて**、ランチャーデータフォルダー **`%APPDATA%\horizon-launcher`**（および作成されていた場合は `%ProgramData%\horizon-launcher-<hash>`）が丸ごと削除される。

- **確かめる所**:
  - エクスプローラー／PowerShell:
    - `%LOCALAPPDATA%\Programs\Horizon Launcher` と **`%APPDATA%\horizon-launcher`** の両方が**消えている**こと。
    - **`%APPDATA%\horizon`**（およびその中の `saves\` フォルダー）が**削除されずに残っている**こと。
